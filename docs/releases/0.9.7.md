# Gather 0.9.7

修复资产日历中延迟股票报价跨日归因的问题，versionCode 21。

- 对于周五下午缓存了盘中价、周六才收到周五后续报价的情况，若记录能证明缓存价已写入且相关账户未修改，将差额回补到周五及后续已有缓存记录，避免周六重复计算。对应 GitHub Issue #4。
- 收入、现金调整和持仓调整保留原日期；缺失日期不补造，数字货币不套用股票交易日规则。
- 资产记录详情显示行情回补时间，并保留原记录时间和原报价时间说明。
- 日志导出目前只有待确认方案，本版本不包含该功能。

## 历史数据与升级

旧版本已经记错但缺少报价依据的历史不会自动重写。相关账户或持仓有修改、跨多个交易日、来源不完整等无法证明安全归因的情况，仍按观察日记录；本修复不是完整历史行情重建。

保留原包名和签名，可覆盖安装。**升级前请在旧版导出加密备份。** 账本格式升级为 schema 6，新版可读取 v1–v5 备份；旧版应用不能读取新版账本或新版导出的备份。需要回退时须保留升级前备份，不能通过删除应用数据解决升级问题。

## 验证范围

合成数据先复现周五仅记跌 0.4% 的错误，修复后验证周五跌 1%、周六为零。已通过 677 项领域／存储／资产／日历／导航／桑基图断言，以及 13 组行情与加密备份检查。覆盖重复刷新、旧报价、周末收入、多资产混合、持仓变更、旧版迁移、跨月缺口、备份往返和失败写入回滚。完整 Java 源码编译通过。

本机正式 APK 已通过包名、版本、不可调试与签名校验，证书与已发布的 v0.7.1、v0.9.6 一致。全新隔离的 Android 35 模拟器验证 v0.9.6 → v0.9.7 覆盖安装及启动：合成账户、持仓和旧快照完整保留；没有变化时不重写旧文件，下一次正常跨日记录写入时迁移到 schema 6，界面显示正常。

GitHub 发布流程还会独立校验 APK 包名、版本、校验和，并将签名证书与 v0.7.1 原版比对；不接受替代签名。尚未验证真实用户账本、真机后台策略及长期行情端点行为。
